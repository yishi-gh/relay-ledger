# 按需采集实施说明

## 目标与范围

保留现有定时采集周期。进入页面时只补采过期的数据源，主动刷新允许越过过期门槛；浏览器重载按进入页面处理。固定自定义历史范围只重新查询本地数据。

- 日志、上游错误、入口错误、渠道快照：成功采集后复用 1 分钟；余额及核算所需充值：复用 5 分钟。
- 看板将请求写入本地看板库，现有采集进程消费；定时和按需任务共用执行入口。采集失败不刷新成功时间，没有新日志的成功采集仍更新成功时间。
- 同一数据源的并发请求合并；主动刷新仍受短期冷却、失败退避限制。源库始终只读。
- 采集完成使相关业务 API 缓存失效。界面保留已有数据，显示采集进度、成功时间及失败原因。
- 服务探测前台 10 秒；共享设置保留已有 30 秒轮询，个人偏好立即生效。

## 执行与验证

顺序：采集协议与持久状态 → 统一调度与 HTTP 接口 → 页面交互 → 隔离测试、类型检查、lint、构建。
预计 60～90 分钟，实际以错误路径和并发验证完成为准。

验收：过期阈值边界、空增量成功、失败不伪装新鲜、并发合并、进程退出后恢复、冷却退避、关闭采集项、同源写入保护、缓存失效、切页和取消、历史范围不补采。测试仅使用临时库、注入任务和隔离 HTTP，不连接真实上游。

不得覆盖用户已有未跟踪组件，不修改生产配置、定时频率、源库及凭据。不引入 WebSocket、消息服务。提交、推送与部署已获用户授权，发布时保留生产配置和运行期数据。

## 风险

面板与采集进程必须一起更新；旧采集进程不能消费新请求时明确提示不可用。同步 SQLite 查询和外部接口仍有耗时，界面不等待采集才显示已有数据。按需采集不能补回历史余额快照；已有账本缺失、边界容差和充值核算约束继续保留。

## 验收结果（2026-11-18）

- 后端：625 项中 624 通过，Windows 不支持的 POSIX 文件权限检查跳过 1 项，无失败。
- 前端：31 项测试、类型检查、lint、生产构建通过；构建仍有大文件体积提示，本次不做无关拆包。
- 真实进程链路：隔离 HTTP 请求入队，独立运行的正式采集入口消费并写入日志副本，源库字节保持不变。其它验证覆盖过期边界、合并、失败退避、缓存失效、切页取消及固定历史范围。
- 隔离验收未连接真实上游、未修改生产配置。上线须一起更新面板、常驻采集进程和前端构建产物；仅使用 cron 的部署不能消费按需请求。
