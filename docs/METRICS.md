# 统计口径

> 本文是数字的唯一权威定义。任何实现（含未来重写）都必须产出与本文一致的结果。
> 改动本文的任何一条，必须同时改动测试，否则视为回归。

## 0. 一句话公式

```text
售出   = Σ 区间内有效日志的 cost
充值   = 累计充值计数器(期末) − 累计充值计数器(期初)      // 首选
成本   = 期初余额 + 期间充值 − 期末余额
利润   = 售出 − 成本
毛利率 = 利润 ÷ 售出
```

成本那一行等价于「上游自己记的期间已消耗额度」，这是它能成立的原因，也是它唯一正确的理由。

## 1. 通用约定

- **币种**：USD，保留到能对齐上游的精度（内部不四舍五入，展示时才截位）。
- **时区**：北京时间 UTC+8，与服务器时区无关。
- **区间**：一律 `[start, endExclusive)` 左闭右开，避免相邻区间重复计数。
- **空值**：无法计算时返回 `null`，前端显示 `—`。**不得返回 0。**

## 2. 售出

**取数**：中转站日志表。

**过滤条件**（必须与实现中的唯一常量保持一致）：

```sql
log_type = 2                      -- 只取消耗记录
AND (token_name IS NULL OR token_name <> 'Model test')
```

`Model test` 是中转站自测流量，不是真实销售，必须排除。

**金额**：日志行的 `cost` 字段。它与 `quota / quota_per_unit` 应当恒等；若出现不一致，说明中转站费率配置变更，属于需要人工确认的异常，不得静默采用其中一个。

**不计入售出的**：充值、退款、订阅费、赠送额度、管理员工单。售出只代表「按量计费的消耗」。

**分组**：按渠道归到上游账户（见第 8 节），再按时间桶分桶。

## 3. 充值

充值有三种来源，**按优先级取第一个可用的**，不得叠加：

### 3.1 首选：累计充值计数器差值

| 上游类型 | 字段 | 说明 |
| --- | --- | --- |
| Sub2API | `/api/v1/auth/me` 的 `total_recharged` | 上游记录的累计充值总额 |
| NewAPI | `/api/user/self` 的 `quota + used_quota` | 剩余 + 已用 = 累计获得额度 |

```text
充值 = 期末计数器 − 期初计数器
```

为什么可靠：消耗时 `quota` 降、`used_quota` 升，两者之和不变，所以差值**与消耗无关**，只反映真实入账。

判定规则：

- 两端都必须是数值才可用。任一端缺失 → 退到 3.2。
- 期末 < 期初（上游重置、换账号、字段语义变化）→ 视为不可用，退到 3.2。
- 计数器为浮点时允许微小负噪声（量级 ~0.002），但不得把负值当消费。

### 3.2 次选：充值流水事件

取看板库 `credit_event` 在区间内的金额之和。NewAPI 有真实的充值（`type=1`）与赠额（`type=4`）流水，Sub2API 没有。

### 3.3 兜底：余额上涨推断

只在 3.1 与 3.2 都不可用时使用，且必须满足：

```text
推断充值 = max(0, 期末余额 − 期初余额 − 区间内已记录的事件金额)
```

- 剩余 ≤ 0 不记录。
- 必须打标（`source = 'balance_delta'`），界面上可与真实流水区分。
- **两端计数器都有值时，禁止推断**——否则同一笔充值会被记两次。
- 该事件的落库时间必须落在区间内部（期初快照之后），不能落在区间末尾，否则会把充值推进下一个时间桶，造成前桶负成本、后桶虚增成本。

## 4. 成本

```text
成本 = 期初余额 + 期间充值 − 期末余额
```

### 4.1 期初 / 期末余额怎么取

- 期初 = 距**桶起点**最近、且偏差不超过 **5 分钟**的余额快照。
- 期末 = 距**桶终点**最近、且偏差不超过 5 分钟的快照。
- 快照允许**略晚于**边界（采集在整点之后执行），但不能早于边界太多。
- 超出 5 分钟即视为该端缺失，**不得借用相邻小时的快照**。

5 分钟的来历：采集固定在整点后的第 10 秒落库，抖动远小于 1 分钟；而一个桶是 60 分钟，任何超过 5 分钟的偏移都说明这一小时真的没采到。

### 4.2 进行中的桶

当区间终点是「现在」时，期末允许退化为「不晚于终点、最多回溯 90 分钟」的快照——这只是为了实时视图能显示，不代表该桶已结算。已结算的桶一律走 4.1。

### 4.3 判定

| 情况 | 结果 |
| --- | --- |
| 期初或期末缺失 | 成本 `null`，原因「缺快照」 |
| 计算出的成本 < 0 | 成本 `null`，原因「无法核算」 |
| 两者都正常 | 成本 = 数值 |

负成本的唯一现实来源是管理员直接改余额（不走充值计数器）。此时账本已经不成立，**必须判为无法核算并暴露出来**，不能给一个负毛利粉饰过去。

## 5. 利润与毛利率

```text
利润   = 售出 − 成本
毛利率 = 利润 ÷ 售出        （售出为 0 时返回 null，不是 0、不是 Infinity）
```

- 成本为 `null` → 利润与毛利率都是 `null`。
- 售出为 0 且有成本 → 利润 = −成本，毛利率 = `null`（无分母）。

## 6. 时间与分桶

- **日桶**：北京时间 00:00 起，24 小时一桶。
- **小时桶**：整点起，1 小时一桶。
- 桶标签用桶起点。

**「近 24 小时」的定义**：24 个整点桶，起点 = 当前小时起点 − 23 小时，终点 = 最新数据时间。**不是**滚动 24 小时。

理由：上游看板的「24 小时」就是 24 个整点桶；用滚动窗口会多算昨日末尾一整小时，两边的数字永远对不上（实测差约 3.4 USD / 5%）。

**「近 7 天 / 30 天」**：按自然日，起点是首个自然日的 00:00。

## 7. 区间合计与覆盖度

上游账户级或渠道级的区间合计，**不做部分求和**：

- 区间内每一桶都算得出成本 → 合计 = 各桶之和，状态「完整」。
- 有任一桶缺失 → 合计 = `null`，并给出 `covered_buckets / bucket_count`（如 11/24），状态「部分」。

理由是口径一致性：把「有成本的桶」和「有售出的桶」混在一起相加，会得出一个看起来合理、实际无意义的毛利率。

图表允许在「当桶有值」时绘制该点，但必须在悬浮说明里标出有多少上游账户因缺快照未计入。

## 8. 归属：渠道 → 上游账户

`site` 是历史命名：`instance.json` 的 `site`、`db/sites/<site.id>.db`、`/api/meta` 的 `site` 都指你部署的这个中转站；`/api/profit` 返回的 `sites[]` 是上游账户，不是中转站。归属规则如下：

- **显式优先**：`accounts[].channels` 里列出的渠道直接归该账户；同一渠道被多个账户显式列出时保留多 owner（既有财务归属算法本轮不变，多 owner 的售出仍按原有单账户口径入账）。
- **自动匹配只补空缺**：只对路由快照中存在、且没有显式 owner 的渠道，用 origin（`http(s) + 小写 host [+ 非默认端口]`，忽略路径/查询/hash，拒绝 userinfo）匹配：账户 `base_url` 同源，或该账户显式拥有的快照渠道同源（API 别名）。
- 候选按账户去重，**恰好一个才自动关联**；多个候选为歧义，归入「未映射」并在路由页标待确认，**不新增多 owner**。
- **停用账户仍参与归属**：账户停用只代表不再采集余额，它的渠道可能还在销售；停用渠道同样参与。
- 找不到归属（零候选）或歧义未确认的渠道 → 归入「未映射」单列，**不得丢弃、不得按比例摊到其它上游账户**。
- 没有上游账户的渠道（如包月订阅型）→ 状态「无成本源」，只统计售出，不参与成本汇总的分母。
- 归属由**当前账户配置 + 当前路由快照**每次请求纯派生，不落库、不记忆上一轮；修改 base_url 或快照更新会改变派生结果，也会影响用当前配置回查历史区间。不存在「从某时刻起生效」的时间版本。

## 9. 已知无法精确的情况

这些不是缺陷，是边界。遇到时必须按表中方式呈现，不能"想办法凑一个数"。

| 情况 | 表现 | 处理 |
| --- | --- | --- |
| 采集断档 | 断档期间的充值会被并入恢复后的第一个区间 | 总额正确、时点偏移；质量区可见 |
| 管理员手工调额 | 表现为充值或负成本 | 负成本判为无法核算 |
| Sub2API 单笔充值 | 只有累计值，拿不到逐笔 | 只保证区间总额 |
| NewAPI 浮点折算 | ±0.002 量级噪声 | 不做平滑 |
| 小时级余额历史 | 没抓就没有，无法回补 | 只能从现在积累 |
| 中转站日志保留期 | 由上游决定，可能随时清理 | 本地必须自留副本 |

## 10. 口径变更清单

改任何一条口径，以下四处必须同时更新，缺一即视为回归：

1. 本文对应段落。
2. 计算该口径的单元测试（含边界：缺失、负值、除零、跨日）。
3. 接口返回的状态与原因字段（`status` / `reason`）。
4. 界面的空值与覆盖度展示。
